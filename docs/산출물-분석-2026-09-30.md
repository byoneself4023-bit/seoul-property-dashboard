## ② 데이터 `data.js`

**무엇을 넣어서** — 국토교통부 RTMS 실거래가 Open API 4종.

| 키 | 엔드포인트 | 대상 |
|---|---|---|
| `apt` | `RTMSDataSvcAptTradeDev` | 아파트 매매 |
| `rh` | `RTMSDataSvcRHTrade` | 연립·다세대 |
| `sh` | `RTMSDataSvcSHTrade` | 단독·다가구 |
| `offi` | `RTMSDataSvcOffiTrade` | 오피스텔 (별도 활용신청 필요) |

서울 25개 자치구 법정동코드 × 2022-01(`START_YM`)~당월 × 4종 = 약 5,700 콤보.
인증키 `RTMS_SERVICE_KEY` 는 GitHub Secrets 로만 넘긴다(명령줄 미사용).

**어떤 로직으로**

- 응답 원본은 `dashboard/.cache/ingest/` 에 5,751개 파일로 캐시(**git 추적 대상**).
  스키마 버전 `CACHE_SCHEMA_VERSION = 3` — 올리면 전량 무효화된다.
- 최근 두 달(직전 완료월 + 당월)은 신고 지연 때문에 캐시를 무시하고 매번 다시 받는다.
- 페이싱: 초당 20요청 / 동시 6 / 워커 6. 2026-08-12 실측으로 정한 값이다.
- 집계 산출물
  - `periods.week` 12기간, `periods.month` 56기간
  - `byDistrict[구].week/.month` — `apt`, `nonApt`, `room{studio/two/three}`,
    `price{under3/under6/over6}`, `direct`(직거래), `cancelled`(취소)
  - 버킷 경계: 면적 40㎡ / 60㎡, 금액 3억 / 6억
  - **취소된 계약은 해제 짝을 제거해 0건 처리**한다(본체·리포트·검증기 공통 규칙)
- `report` 블록 5개를 같은 실행에서 만든다 (§3 참조).
- `inject()` 가 `data.js` 를 쓰고 `dashboard.html` 의 `?v=` 를 내용 sha256 앞 8자로 갱신한다.
  `<script src="data.js">` 참조가 없으면 **예외를 던져 수집이 실패한다**.

**언제 도나** — `.github/workflows/ingest.yml`
- cron `0 22 * * 0` (UTC 일 22:00 = **KST 월 07:00**) + 수동 실행(`fresh` 옵션)
- 성공하고 **실제로 데이터가 바뀐 경우에만** `ingest/<타임스탬프>` 브랜치로 PR → squash 병합
  (`main` 은 ruleset 보호, 요구 승인 0건) → `gh workflow run report.yml` 호출
- 로컬 launchd `com.kuka.dashboard-ingest` 는 **내려가 있다**. 확인:
  `launchctl list` 에 없음, plist 는 `.disabled` 로만 존재. 즉 수집 경로는 러너 하나뿐이다.

**실제로 돌았나 (ingest.yml 최근 10회)**

```
2026-09-28  성공   ← 현재 라이브 데이터
2026-09-20  실패   19m43s
2026-09-13  성공
2026-09-06  성공
2026-09-03  성공 ×2 (수동), 실패 ×1 (수동)
2026-08-31  실패
2026-08-23  실패
2026-08-16  실패
```

- **2026-09-20 실패의 원인은 코드가 아니라 상류 API** 다. 로그에 `[실패] 11110/202608/apt:
  fetch failed` 가 연속으로 찍히고 진행 500/5700(9%) 시점에 실패 11건 → 잡 종료.
  data.go.kr 쪽 응답 실패로 보인다. 재시도 없이 다음 주(9/28)에 정상 복구됐다.
- 08-16 / 08-23 / 08-31 세 번의 실패는 `actions: write` 권한 누락으로 발행 호출이
  403 이 나던 건이고, 이미 워크플로에 권한이 추가돼 해결됐다(주석에 기록돼 있다).

## ③ 리포트 PNG 5장

**무엇이 나오나** — 1240×1400 뷰포트, `deviceScaleFactor: 2` 로 찍은 PNG 5장.

| 파일 | 블록 | 내용 |
|---|---|---|
| `01.png` | `#rptBlock1` | 아파트 신고가·신저가 |
| `02.png` | `#rptBlock2` | 거래 1위 (구 / 동 / 단지) |
| `03.png` | `#rptBlock3` | 비아파트 (연립·다세대 + 오피스텔) |
| `04.png` | `#rptBlock5` | 월별 거래량 추이 |
| `05.png` | `#rptBlock4` | **재건축·재개발 신규 지정 / 해제** |

파일명이 ASCII 번호인 이유는 외부 사이트가 참조하는 URL 에 한글 퍼센트 인코딩을
넣지 않기 위해서다. 렌더 스크립트 안에서는 `out/매주/…`, `out/월간/정비사업.png` 로
발행 주기를 갈라 두고, 워크플로가 `01~05.png` 로 옮겨 담는다.

**어떤 로직으로** — `render-report.mjs` 가 `verify-report.mjs` 를 **먼저** 부르고,
검증 실패면 PNG 를 쓰지 않고 `exit 1`. 그 실패가 곧 잡 실패이고 발행이 막힌다.
즉 검증을 통과하지 못한 그림은 라이브에 나가지 않는다. `document.fonts.ready` 와
`requestAnimationFrame` 2회를 기다린 뒤 요소 단위로 캡처한다.

**언제 도나** — `report.yml`. **cron 이 없다.** ②가 데이터 병합 직후 호출하거나,
사람이 Actions 탭에서 수동 실행. PNG 가 바이트까지 같으면 커밋 없이 발행만 부른다.

**실제로 돌았나** — 2026-09-28T00:15Z 성공 (run 36361535760). 저장된 날짜 폴더:
`2026-09-03`, `2026-09-06`, `2026-09-13`, `2026-09-28`, `latest`.
(9/20 은 수집이 실패했으므로 폴더가 없다.)

**어디서 보나 (HTTP 실측 2026-09-30)**

```

/reports/latest/05.png       200  431,723B
```

## ④ 정비사업 신규 지정 / 해제 — **자동으로 들어오지 않는다**

질문의 핵심 항목이라 따로 둔다.

### 결론

**서울시 신규 공시는 매주 자동으로 들어오지 않는다.** 수집기는 완성돼 있고
화면·PNG 까지 경로가 다 뚫려 있지만, **이 수집기를 부르는 워크플로가 없다.**

### 근거

```
$ grep -rn "ingest-rebuild|SEOUL_OPENAPI" .github/ dashboard/scripts/ package.json
.github/claude-ci-settings.json:50   "Bash(node dashboard/ingest-rebuild.mjs --selftest)"
.github/claude-ci-settings.json:75   "Bash(node dashboard/ingest-rebuild.mjs)"
```

걸린 것은 에이전트 permission 목록 두 줄뿐이다. `ingest.yml` 은 `ingest.mjs` 만 돌리고,
`ingest.mjs` 는 `loadRebuildCache()` 로 **디스크 캐시를 읽기만 한다** — API 를 부르지 않는다.
코드 주석도 그렇게 말한다: *"이 캐시는 … 수집 워크플로가 아직 없다(월 1회 수동 실행)."*

### 어디까지 만들어져 있나

| 조각 | 상태 |
|---|---|
| 출처 조사 | 완료 — `docs/정비사업-데이터-확인.md` (2026-08-12, API 76회 실호출 실측) |
| 수집기 | 완성 — `dashboard/ingest-rebuild.mjs` 759줄. `--fresh` / `--selftest` 지원 |
| 캐시 | 51개 파일, git 추적 중 (`dashboard/.cache/rebuild/`) |
| 집계 | `ingest.mjs` 의 `buildRebuildBlock()` — `data.js` 의 `report.rebuild` 로 들어감 |
| 화면 | 리포트 탭 `#rptBlock4` — 좌 신규 지정 / 우 해제, 각 10건 |
| 이미지 | `05.png` 로 매주 같이 발행됨 |
| **자동 수집** | **없음** ← 유일하게 빠진 조각 |

### 어디서 가져오나 (수동 실행 시)

서울 열린데이터광장 Open API 2종. 인증키는 `.env` 의 `SEOUL_OPENAPI_KEY`.

```
OA-20281 upisRebuild       정비사업 현황 — RPT_TYPE 으로 신설/변경/폐지/실효 구분
   └─ DCSN_ANCMNT_MNG_CD ─→ ANCMNT_MNG_CD
OA-20283 upisAnnouncement  결정고시 정보 — 고시일 ANCMNT_YMD 공급원 (조인 99.0% 성립)
```

- **신규 지정** = `RPT_TYPE = '신설'`
- **해제** = `RPT_TYPE ∈ {'폐지','실효'}`
- 고시 제목(`TTL`)으로 해제를 찾으면 안 된다 — 2020년 이후 해제의 26%만 걸린다.
  상위 재정비촉진계획 변경에 딸려 폐지되는 건이 많아 제목에 "해제"가 없다.
- 2024-01 이후 고시일 기준으로 잘라 상위 10건씩. 구역명·소재지·고시일이 같은
  중복(성수전략정비구역 1~4지구 등)은 묶고 `zones` 로 개수를 적는다.
- 자치구는 `PSTN_NM` 에서 추출한다. 원본에 구가 없으면 **동 이름으로 유추하지 않고
  `null` 로 둔다** (예: "중화2동 309-39번지 일대").

### 왜 멈춰 있는가 (추정 아님 — 문서에 남아 있는 것)

`docs/정비사업-데이터-확인.md` §7: 이 4종은 **공공누리 4유형**(출처표시 +
상업적 이용금지 + **변경금지**)이다. 국토부 실거래(1유형)와 조건이 다르다.
대시보드는 본질적으로 집계·시각화라 "변경금지"와 정면으로 만난다는 판단이
문서에 적혀 있고, 결론은 내리지 않은 채 세 갈래(별도 이용허락 / 비영리 한정 /
항목 제외)를 열어 뒀다. 이슈 #7 "정비사업 데이터 수집기 — 신규 지정 / 해제
(**구현만**)" 이 **열린 채로 남아 있다.** 자동화가 빠진 것이 실수인지 보류인지는
「확인 못 함」이나, 정황은 의도적 보류 쪽이다.

## ⑤ 신선도 감시 → 이슈 알림

**무엇이 나오나** — 라벨 `데이터-정지` 가 붙은 GitHub 이슈. 열린 것이 있으면 중복 생성 안 함.

**어떤 로직으로** — 저장소를 checkout 하지 않고 **라이브를 curl 로 직접** 본다.
`/` 200 확인 → `/data.js` 200 확인 → `generatedAt` 파싱 → 나이 계산.
`MAX_AGE_DAYS = 7` 초과면 실패 + 이슈. 설계 의도는 *"돌지 않은 작업은 실패하지도
않는다"* 를 명시적 실패로 바꾸는 것이다.

**언제 도나** — cron `0 0 * * *` (UTC 00:00 = **KST 매일 09:00**).

**실제로 돌았나**

```
2026-09-30  성공     ← 수집일 2026-09-28, 2일 경과
2026-09-29  성공
2026-09-28  성공
2026-09-27  실패  ┐
   …             ├ 9/20 수집 실패의 여파로 7일 연속 실패
2026-09-21  실패  ┘  → 이슈 #39 생성
2026-09-20  성공
```

**남아 있는 문제** — 이슈 #39 "라이브 데이터가 갱신되지 않고 있다" 는 9/21 에 열렸고
9/28 에 데이터가 정상화됐는데도 **아직 열려 있다.** 워크플로에 자동 닫기가 없다
(본문에 "고쳐서 라이브가 갱신되면 이 이슈를 닫는다" 라고 사람에게 맡겨 뒀다).
열려 있는 동안은 중복 생성이 막히므로, **다음번 진짜 정지 때 새 이슈가 안 열린다.**

## ⑥ 개발 지원 워크플로 (제품 산출물 아님)

| 워크플로 | 하는 일 | 트리거 | 상태 |
|---|---|---|---|
| `verify.yml` 품질 게이트 | `npm run verify` — puppeteer 로 콘솔 에러 0 / 원격 리소스 규율 / 모바일 폭 검사 | 화면·데이터 건드리는 PR, 수동 | 사람 PR 에서는 정상 통과(9/5 4건 성공) |
| `claude.yml` 에이전트 | 이슈·PR 의 `@claude` 멘션 처리, Draft PR 생성 | 멘션 | — |
| `auto-pr.yml` | 에이전트 브랜치 → Draft PR (백스톱) | `claude/**` push, 수동 | — |

**확인된 이상** — 자동 수집 PR 에서 품질 게이트가 **0초 만에 잡 없이 failure** 로 끝난다.

```
2026-09-28  failure          0s   ingest/20260928-001514   (jobs: [])
2026-09-13  action_required  0s   ingest/20260913-235102
2026-09-06  failure          2s   ingest/20260906-232444
```

`jobs` 가 빈 배열이므로 잡이 시작조차 못 한 startup failure 다. 봇이 연 PR 에 대한
워크플로 승인 정책과 관련된 것으로 보이나 **원인은 「확인 못 함」**. 결과적으로
**수집 PR 은 품질 게이트를 실제로 통과하지 않고 병합된다.** 다만 리포트 쪽은
`verify-report.mjs` 가 렌더 직전에 별도로 돌아 그쪽 검증은 살아 있다.
