## 1. 왜 분리했나

`dashboard.html`이 756,812 B / 24,887줄이었고 그중 **476,899 B(63.0%) / 23,680줄이

## 2. 인라인이었던 이유 — 확인 결과

작업 전에 설계 근거를 확인했다. **두 가지였고, 하나는 해소되고 하나는 폐기했다.**

### 이유 1 — `file://` CORS 제약 (해소됨)

`~/Project/dashboard/docs/실데이터_연동_가이드.md:8` 변경 전 원문:

> 배포 없이 "파일 열기" 모델을 유지하기 위해, 인제스트 스크립트(`ingest.mjs`)가 API를
> 호출·집계해 결과 JSON을 **`dashboard.html` 안에 인라인**한다. 브라우저는 `file://`에서
> 외부 JSON을 `fetch`하지 못하므로(로컬 CORS 차단) 인라인 방식이 필수다.

`fetch`는 막히지만 **`<script src>` 로드는 `file://`에서도 동작**한다. 따라서 script 태그
방식으로 바꾸면 "파일 열기" 모델을 유지한 채 분리할 수 있다. 이 제약은 해소된다.

### 이유 2 — 단일 파일 전달 모델 (폐기 결정)

같은 문서 `:120` 변경 전 원문:

> 남에게 **전달한 dashboard.html 은 전달 시점의 스냅샷**이며 자동으로 갱신되지 않는다
> (인라인 데이터 단일 파일 모델).

`~/Project/CLAUDE.md:11`도 `자기완결형 단일 파일`,
`~/Project/dashboard/dashboard.html:7` 주석도 `self-contained … 오프라인/미리보기에서도
정상 렌더`라고 적고 있었다. 커밋 `b802893 feat(dashboard): 자기완결형 HTML + Pages 자동
배포 스크립트`는 CDN 의존을 **의도적으로 제거**한 커밋이다.

**대표 판단으로 이 모델은 폐기했다** — 데이터가 계속 쌓이는데 한 파일에 담는 구조는
유지가 불가능하고, 전달은 GitHub Pages 링크로 한다. 관련 문서 4곳을 함께 갱신했다(§6).

## 4. 코드 변경

### 4-1. `ingest.mjs` — `inject()` 재작성

`~/Project/dashboard/ingest.mjs:595-631` 변경 후 전문:

```javascript
function inject(normalized) {
  const htmlPath = join(__dirname, 'dashboard.html');
  const jsonPath = join(__dirname, 'data.json');
  const jsPath   = join(__dirname, 'data.js');

  const jsonStr = JSON.stringify(normalized, null, 2);

  // dashboard.html 은 더 이상 데이터를 담지 않는다(2026-08-12 데이터 분리).
  // 다만 화면이 data.js 를 로드하지 않는 상태로 어긋나면 수집이 조용히 무의미해지므로,
  // 참조 존재 여부만 검사한다. 실패 = 진짜 오류.
  const html = readFileSync(htmlPath, 'utf8');
  if (!/<script\s+src="data\.js"/.test(html)) {
    throw new Error(
      'dashboard.html 에서 <script src="data.js"> 참조를 찾지 못했습니다.\n' +
      '       화면이 데이터를 로드하지 못하는 상태입니다. dashboard.html을 확인하세요.'
    );
  }

  // data.js — 화면이 읽는 파일. file:// 에서도 로드되도록 fetch가 아닌 script 태그 방식.
  const jsStr =
    '// 자동 생성 파일 — 직접 수정하지 마세요. dashboard/ingest.mjs 의 inject()가 씁니다.\n' +
    `// 생성: ${normalized.generatedAt}\n` +
    `window.__DASHBOARD_DATA__ = ${jsonStr};\n`;

  // data.json — 동일 내용의 표준 JSON. 리포트 계산·SQLite 전환 등 다른 프로그램용 중간 재료.
  writeFileSync(jsonPath, jsonStr, 'utf8');

  // 데이터 무변경(동일 스냅샷) = 정상 no-op. data.js 갱신 생략.
  const prevJs = existsSync(jsPath) ? readFileSync(jsPath, 'utf8') : null;
  if (prevJs === jsStr) {
    console.log('[ingest] 데이터 변경 없음 — data.js 갱신 생략 (data.json만 저장)');
    return;
  }

  writeFileSync(jsPath, jsStr, 'utf8');
  console.log(`[ingest] data.js 저장 완료 (generatedAt: ${normalized.generatedAt})`);
  console.log(`[ingest] data.json 저장 완료`);
}
```

**슬롯 정규식 교체가 사라져 로직이 단순해졌다.** `dashboard.html`은 이제 읽기만 한다.
멱등·no-op 성질(데이터 무변경 시 파일 미갱신)은 그대로 유지했다.

슬롯 부재 검사를 없애지 않고 **`data.js` 참조 검사로 대체**했다. 참조가 사라지면 수집이
성공해도 화면은 목데이터를 띄우게 되는데, 이 경우 조용히 실패하는 것보다 즉시 멈추는
편이 낫다.

### 4-3. `deploy.sh` — 5곳 수정

단일 파일을 전제하던 지점을 전부 고쳤다.

| 지점 | 변경 |
|---|---|
| `SRC` 정의 | `SRC_DATA="$PROJECT/dashboard/data.js"` 추가 |
| 원본 존재 검사 | `data.js` 부재 시 `fail` (ingest 먼저 실행하라는 안내 포함) |
| **수집일 추출원** | `dashboard.html` → **`data.js`**. 분리 후 HTML에 `generatedAt`이 없다 |
| provenance dirty 판정 | `git diff --quiet -- dashboard.html data.js` (둘 다 검사) |
| no-op 판정 | 두 파일 모두 동일할 때만 스킵 |
| 복사·커밋 | `cp` 2회, `git add index.html data.js` |
| **라이브 검증** | `index.html`과 `data.js`를 **각각** HTTP 200 + sha 대조 |

수집일 추출 부분 (`~/Project/dashboard/scripts/deploy.sh:39-43`):

```sh
# 데이터 수집일(generatedAt) 추출 — 커밋 메시지에 사용
# 데이터 분리 후 generatedAt 은 dashboard.html 이 아니라 data.js 에 있다.
DATA_DATE="$(grep -oE '"generatedAt"[[:space:]]*:[[:space:]]*"[0-9]{4}-[0-9]{2}-[0-9]{2}' "$SRC_DATA" \
             | grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}' | head -1)"
[ -n "$DATA_DATE" ] || fail "generatedAt(수집일) 추출 실패 — data.js 확인"
```

라이브 검증 부분 (`~/Project/dashboard/scripts/deploy.sh:94-111`):

```sh
# 라이브 검증: 화면(index.html)과 데이터(data.js) 각각 HTTP 200 + sha 일치.
# data.js 까지 봐야 수집일이 실제로 라이브에 반영됐는지 확인된다 —
# 데이터 분리 후 index.html 에는 generatedAt 이 없다. 엣지 전파 재시도 포함.
TMP_LIVE="${TMPDIR:-/tmp}/deploy-live.$$"
i=0; ok=0; code=""; code_data=""
while [ "$i" -lt 18 ]; do
  code="$(curl -s -o "$TMP_LIVE" -w '%{http_code}' -L "$LIVE_URL")"
  if [ "$code" = "200" ] && [ "$(shasum -a 256 "$TMP_LIVE" | awk '{print $1}')" = "$WANT_SHA" ]; then
    code_data="$(curl -s -o "$TMP_LIVE" -w '%{http_code}' -L "${LIVE_URL}data.js")"
    if [ "$code_data" = "200" ] \
       && [ "$(shasum -a 256 "$TMP_LIVE" | awk '{print $1}')" = "$WANT_SHA_DATA" ]; then
      ok=1; break
    fi
  fi
  i=$((i + 1)); sleep 5
done
```

no-op 판정은 **둘 다 같을 때만** 스킵한다. 하나라도 다르면 둘 다 올린다 — 화면과 데이터가
어긋난 상태로 라이브에 남지 않게 하기 위해서다.

`sh -n dashboard/scripts/deploy.sh` 문법 검사 통과. **실행은 하지 않았다.**

### 4-4. `verify-quality.mjs` — 원격 리소스만 세도록 수정

기존 검사는 `script[src]` 개수를 세어 `외부 리소스 2개 이하`를 강제했다. 로컬 상대경로인
`data.js`까지 함께 세므로 게이트의 의도("신규 CDN 금지")와 어긋난다.

`~/Project/dashboard/verify-quality.mjs:24-32` 변경 후:

```javascript
  // 외부(원격) 리소스만 센다 — 로컬 상대경로(data.js 등)는 CDN 의존이 아니므로 제외.
  // 2026-08-12 데이터 분리로 <script src="data.js"> 가 생겼는데, 이걸 CDN으로 세면
  // 게이트의 의도("신규 CDN 금지")와 어긋난다.
  remoteResources: [...document.querySelectorAll('script[src], link[rel="stylesheet"][href]')]
    .map(el => el.getAttribute('src') || el.getAttribute('href') || '')
    .filter(v => /^(https?:)?\/\//.test(v)).length,
  localScripts: [...document.querySelectorAll('script[src]')]
    .map(el => el.getAttribute('src') || '')
    .filter(v => !/^(https?:)?\/\//.test(v)),
```

게이트 조건도 `외부 리소스 2개 이하` → **`원격 리소스 0건`**으로 조였다. 로컬 스크립트
목록은 참고 지표로 출력한다(현재 `data.js`).

## 8. 캐시 무효화 (2026-08-12 추가)

### 8-1. 왜 필요했나 — 낡음이 아니라 **어긋남**

GitHub Pages의 실제 캐시 정책을 라이브에서 측정했다:

```
$ curl -sI -L https://byoneself4023-bit.github.io/seoul-property-dashboard/
HTTP/2 200
cache-control: max-age=600
etag: "6a548921-b6c1d"
via: 1.1 varnish
```

다른 Pages 사이트의 CSS·HTML도 전부 `max-age=600`이었다. **Pages는 모든 정적 자산에
10분 TTL + ETag를 고정 적용하며 커스텀 헤더를 지원하지 않는다**(Netlify·Cloudflare
Pages의 `_headers` 같은 기능 없음). 따라서 낡음 자체는 최대 10분이고, 주 1회 갱신되는
데이터에서 10분은 실질적 문제가 아니다.

**진짜 위험은 두 파일이 서로 다른 시점에 캐시되는 것이다.** `index.html`은 재검증되어
새 버전을 받았는데 `data.js`는 아직 자기 TTL 안이라 캐시에서 나오면, **새 화면 + 낡은
숫자** 조합이 만들어진다. 오류 없이 조용히 틀린 값을 보여주므로 알아챌 방법이 없다.

버전 쿼리의 본질적 효용은 캐시 무효화가 아니라 **짝 강제**다. `data.js?v=X`를 요청하는
HTML은 반드시 X 버전 데이터를 받는다 — 낡은 HTML이 캐시에서 나오면 낡은 v를 요청해
낡은 짝을, 새 HTML이면 새 v를 요청해 새 짝을 받는다. 어느 쪽이든 어긋나지 않는다.

### 8-2. 쿼리스트링이 Pages에서 동작하는가 — 한다

```
?（없음）      HTTP/2 200  etag: "6a548921-b6c1d"  x-cache: HIT
?v=2026-08-12  HTTP/2 200  etag: "6a548921-b6c1d"  x-cache: HIT
?v=abcd1234    HTTP/2 200  etag: "6a548921-b6c1d"  x-cache: HIT
```

쿼리가 붙어도 404가 나거나 내용이 달라지지 않는다. 엣지(varnish)는 쿼리를 무시하고
동일 객체를 반환하지만(`age`·`x-cache-hits` 동일), **문제가 되지 않는다.** 스테일
데이터를 만드는 계층은 엣지가 아니라 브라우저 캐시이고, 브라우저는 쿼리를 포함한 전체
URL로 캐시를 키잉하기 때문이다. 필요한 계층에서 정확히 동작한다.

### 8-3. 수집일이 아니라 **내용 해시**를 쓴다

수집일(`generatedAt`) 기반 `?v=2026-08-12` 방식에는 결함이 있다. **같은 날 데이터가
여러 번 바뀐다.** 2026-08-12 하루에만 수집이 3회 돌았고(커밋 `da5dc5a`의 의도치 않은
수집, 전량 재수집, `data.js` 생성), 실측 결과 내용이 실제로 달랐다:

```
generatedAt: 2026-08-12 == 2026-08-12  (같음)
총 거래건수: 450,778 → 453,216  (차이 +2,438)
내용 동일? False
```

날짜 기반이었다면 세 번 모두 `?v=2026-08-12`라 브라우저가 낡은 `data.js`를 계속 썼을
것이다. 재수집·수동 재실행·실패 후 재시도는 앞으로도 같은 날 여러 번 일어난다.

**`data.js` 내용의 sha256 앞 8자**를 쓴다. 내용이 바뀔 때만, 그리고 바뀌면 반드시
값이 바뀐다. 내용이 같으면 해시도 같으므로 멱등성이 오히려 더 정확해진다(날짜 방식은
데이터가 그대로여도 날이 바뀌면 HTML을 건드린다).

### 8-4. 검토한 다른 방식

| 안 | 판단 |
|---|---|
| **내용 해시 쿼리** `data.js?v=a1b2c3d4` | **채택** |
| 수집일 쿼리 `?v=2026-08-12` | 같은 날 재수집 시 무효화 실패(§8-3에서 3회 재현) |
| 해시 파일명 `data.a1b2c3d4.js` | 동일 효과지만 Pages가 TTL을 600초로 고정해 **이점 없음**. 구 파일 정리·배포 복잡도만 증가 |
| 아무것도 안 함 (ETag+600초) | 낡음 10분은 감수 가능하나 **어긋남을 못 막음** |
| `<meta http-equiv="Cache-Control">` | 하위 리소스에 적용되지 않음 — 동작 안 함 |
| `fetch(..., {cache:'no-store'})` | `file://` CORS로 로드 불가 — 분리의 전제를 깸 |
| 런타임 `?v=Date.now()` 동적 삽입 | HTML은 불변이나 매 로드마다 477KB 재다운로드. 캐시 이점 전무 |

### 8-5. 구현

`~/Project/dashboard/ingest.mjs:596-650` `inject()`:

```javascript
  // 캐시 버스팅 버전 — data.js 내용의 sha256 앞 8자.
  // 수집일(generatedAt)이 아니라 내용 해시를 쓰는 이유: 같은 날 재수집·수동 재실행·
  // 실패 후 재시도로 하루에 여러 번 데이터가 바뀐다(2026-08-12에 실제로 3회).
  // 날짜 기반이면 그 경우 버전이 그대로라 브라우저가 낡은 data.js를 계속 쓴다.
  // 내용이 같으면 해시도 같으므로 멱등성은 오히려 더 정확해진다.
  const version = createHash('sha256').update(jsStr).digest('hex').slice(0, 8);
```

```javascript
  // ── dashboard.html 의 버전 쿼리 ──
  // 항상 "있어야 할 값"으로 맞춘다(자기 치유). 이미 같으면 파일을 건드리지 않는다.
  const newHtml = html.replace(srcRe, `$1?v=${version}$3`);
  if (newHtml === html) {
    console.log('[ingest] data.js 버전 동일 — dashboard.html 갱신 생략');
    return;
  }
  writeFileSync(htmlPath, newHtml, 'utf8');
```

참조 검사 정규식은 쿼리스트링을 허용하도록 바꿨다 —
`const srcRe = /(<script\s+src="data\.js)(\?v=[^"]*)?(")/;`. 이 검사는 **모든 쓰기보다
먼저** 수행되므로, 참조가 사라진 상태에서는 `data.json`·`data.js` 어느 것도 건드리지
않고 즉시 멈춘다.

`~/Project/dashboard/dashboard.html:189-194`:

```html
<!-- 데이터: ingest.mjs 가 생성하는 data.js (window.__DASHBOARD_DATA__).
     fetch가 아닌 script 태그라 file:// 로 직접 열어도 로드된다.
     파일이 없으면 목데이터 폴백으로 동작한다.
     ?v= 는 data.js 내용의 sha256 앞 8자 — inject()가 갱신한다. 직접 고치지 말 것.
     브라우저가 낡은 data.js 를 쓰는 것(= 새 화면 + 낡은 숫자)을 막는다. -->
<script src="data.js?v=4a14749a"></script>
```

### 8-6. `inject()`의 "읽기만 한다" 전제와 `deploy.sh` 영향

**`inject()` — 전제가 깨져 쓰기 경로를 복원했다.** 다만 멱등성은 유지된다: 해시가
같으면 HTML을 건드리지 않는다. §4-1에서 없앤 정규식 치환이 돌아왔지만 대상이 슬롯
23,680줄이 아니라 `src` 속성 한 곳이다.

**`deploy.sh` — 수정 불필요.** 조사 단계에서 이미 두 파일을 함께 다루도록 고쳐 뒀다.

- dirty 판정: `git diff --quiet -- dashboard/dashboard.html dashboard/data.js` — 둘 다 검사
- no-op 판정: `cmp -s "$SRC" "$DEST" && cmp -s "$SRC_DATA" "$DEST_DATA"` — 둘 다 동일할 때만 스킵

오히려 **더 정확해진다.** 데이터가 바뀌면 HTML의 해시도 바뀌므로 두 조건이 항상 함께
움직이고, 한쪽만 배포되는 경우가 구조적으로 사라진다.

### 8-9. 감수한 비용

`dashboard.html`이 데이터 변경 시마다 바뀌므로 **커밋마다 280KB blob이 새로 쌓인다.**
`data.js` 477KB와 합쳐 수집 1회당 약 757KB로, 인라인 시절(750KB)과 비슷한 수준이다.
현재 저장소는 loose object 1,283개 / 50.98 MiB이고 `git gc`가 한 번도 돌지 않았다
(`size-pack: 0`). 주 1회 수집이면 연 39MB 증가다.

이는 해시 한 줄 때문이 아니라 **데이터를 git에 넣는 구조 자체의 비용**이므로, §7의
"`data.js` git 추적 여부" 결정과 함께 판단한다. 완화책은 `data.js`를 gitignore로
돌리거나 `git gc`를 주기적으로 실행하는 것이다.
